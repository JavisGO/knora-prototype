# Knora 产品蓝图原型

入口页面：`index.html`，用 Chrome 直接打开即可。

## 协作流程

所有改动都在分支上做，通过合并请求（Pull Request）合入 `main`，不能直接推送到 `main`。

1. **开工前同步**：切回 `main`，拉取（Pull）最新版本。
2. **新建分支**：一个需求一个分支，名字写清楚做什么，例如 `kb-upload-config`。
3. **修改并提交**：改完存一个版本（Commit），说明写清楚改了哪个页面、改了什么。
4. **推送分支**：推送（Push）到 GitHub。
5. **提合并请求**：在 GitHub 上提 Pull Request，标题写需求名称，描述写改了哪些页面。
6. **合并**：没有冲突就点 Merge；有冲突时，在合并前先选好保留哪一边。
7. **合并后**：分支会自动删除，其他人开工前拉取一下就能拿到最新版本。

## 约定

- 每次迭代开始时说清楚谁改哪几个页面，公共文件（`assets/` 下的共享样式和脚本、侧边栏、首页导航）由一个人负责修改。
- CSS 保持一条规则一行，不要压缩成一行，否则合并时容易误判冲突。
- 验证截图、临时文件放在 `_qa/`、`qa/`、`tmp/` 里，这些目录不会上传。
- 标签 `baseline-v4` 是原样导入的基线版本，需要时可以随时找回。
